Ce qui tient bien

La liste par jour et ses vignettes de 44 dp ; toutes les cibles d'icône à 48 dp ; l'absence de filets ; les masses en opacités du texte, fidèles au Mac ; la barre flottante du bas ; la pastille à deux gestes ; des contrastes de texte sains en clair (27 couples uniques sur 30 passent WCAG et APCA) ; les images décoratives toutes cachées à TalkBack ; tous les boutons d'icône nommés. Les recos ne touchent pas à cela.

Comment ce dossier a été fait

  1. Lu : DESIGN.md, TEXTES.md, SPEC-telephone.md, marque/README.md, les captures du Mac 0.24.0, tout le code de phone/android (5 399 lignes) et l'historique complet des choix (git log -S sur 916 commits).
  2. Relevé : une copie du banc, hors du dépôt, rejoue 24 états en 6 variantes et relève l'arbre des vues ; un script lit le code pour inventorier chaque valeur. Aucune ligne du code de l'app n'est changée.
  3. Mesuré : WCAG 2.2 et APCA pour chaque texte dessiné et chaque icône, cibles, débordements, sémantique, typographie, poids.
  4. Sourcé : chaque reco cite un critère WCAG, une page Android, le code source de Material Components (Typography.md, List.md, datepicker/styles.xml, ProgressIndicator.md, FloatingToolbar.md) ou une règle de DESIGN.md. Les pages de m3.material.io ne se lisent pas sans JavaScript : elles ne sont pas citées. Les comportements d'apps Google que je n'ai pas pu vérifier ne sont pas cités non plus.
  5. Prototypé : 13 écrans en HTML/CSS au dp près, avant et après, clair et sombre.
